# Simplify-first, observable and bounded

Historical successful sequence: discover the extension on each supported page, Autofill This Page, wait for an observable completion, inspect Need review and required/material fields, then prefer Continue Application. Navigation invalidates old control references. This is prior workflow knowledge, not a claim that every current portal is supported.

The small `job_applier/simplify_boundary.py` helper discovers the installed extension's shadow-root controls, records only bounded metadata and verifies page/field-state changes. It is not another filler, an authentication engine, or a submission engine. The stand-in HTML fixtures are explicitly synthetic.

- Before triggering, confirm the attempt owner and exact page target.
- Do not retrigger an already attempted unchanged page.
- Missing, unsupported, disabled or stale controls produce explicit fallback reasons.
- Active/unknown extension writing forbids another browser writer. After a timeout, writer state remains unknown until reconciled; a timer expiry is not proof that the extension stopped.
- When quiescent, preserve filled sections and choose a bounded recovery: native observation, selector adjustment, approved helper, targeted deterministic residual handling, or an authenticated checkpoint.
- Extension completion is not proof that all fields are correct. Verify critical fields while filling, not through a repeated full review-page audit.
- Routine screenshots stay off; capture only when selected policy and a concrete diagnosis require it, using private artifact storage.
