# Simplify-first execution (shared across ATS platforms)

Simplify is the bulk filler; the harness supervises forward progress, not field perfection.

1. Observe the exact owned target and the extension's live shadow-root controls.
2. While account/autofill writing is active, wait. Unknown state is not permission for a manual write.
3. After observable quiescence, prefer enabled Continue Application even if review warnings remain. If unavailable, try the native advancement control once where the platform procedure supports it.
4. Trigger an available Autofill This Page on a new page. Do not repeatedly rerun it on the same page just because optional fields are blank.
5. After actual rejected advancement/no progress, permit one available Simplify retry. If it fails, address only the concrete required blocker from approved facts. Do not invent answers, parse PDFs, or reconstruct work/education history.
6. Preserve filled sections and approved attachments. Routine auth uses configured native credentials, not Simplify-generated passwords.
7. Before an authorized submission keep the existing submission-intent and exact-target guards; verify the employer's result afterward. A Simplify success panel alone is not evidence of submission.

`SimplifyBoundary(..., fast=True)` enables forward-first policy for supported callers; default conservative behavior remains compatible. The Workday runner is the production fast-loop entry point and keeps retry counters across bounded calls. Other ATS platforms inherit the shared procedure but do not automatically receive Workday-specific navigation code.

Use `CDPPage.evaluate_function` for shipped JavaScript functions with JSON arguments. Use ordinary `evaluate` for expressions/IIFEs. Never clear writer state merely because a sleep elapsed.
